# Project Limitations

Honest assessment of what this system can and cannot do. Read before interpreting any output.

---

## 1. The Model Is Frozen in 2015

The LightGBM model was trained exclusively on USAID SCMS shipment data spanning **2006-2015**. Every prediction - regardless of what "scenario year" you select - uses 2015 as the effective year feature internally (`min(year, 2015)`).

- **What this means:** Selecting 2026 or 2030 does not give you a 2026 or 2030 forecast. It gives you a 2015-era model prediction with a 2026 label.
- **Why it matters:** Freight costs changed dramatically post-2015 (COVID supply chain shocks, fuel price spikes, Red Sea disruptions). The model has no knowledge of any of this.
- **The UI is honest about this** via captions, but it is easy to miss.

---

## 2. UNCTAD Rate Is a Structural Benchmark, Not a Real Rate

The UNCTAD `unctad_rate_usd_kg` feature is pulled from a lookup table covering **2016-2021**. It is a destination-tier signal (regional average), not a lane-specific or time-matched rate.

- It is used as a structural enrichment to tell the model "this destination tier is generally cheaper/more expensive."
- It is **not** a live market rate and should never be read as one.
- It is **not** a tariff.
- It is **not** a freight-rate forecast.
- For post-2021 predictions, the same 2021 value is reused as a frozen benchmark.

---

## 3. Origin Country Data Quality Is Imperfect

Origin countries are extracted from the "Manufacturing Site" free-text field using a heuristic (last comma-separated segment). Despite the fix to filter company suffixes:

- Some entries may still be misclassified (e.g. a city name extracted instead of a country).
- The dropdown only reflects manufacturers that shipped to USAID's network - predominantly India, South Africa, and a handful of European countries. It is not a general list of origin countries.
- Countries not in the training data will have no observed route-mode history, so all modes are shown as available by default.

---

## 4. Geographic Feasibility Check Is Continent-Level Only

The truck feasibility warning (`_truck_feasible`) checks whether origin and destination are on the same continent. This catches obvious impossibilities (USA -> Kenya by truck) but **misses**:

- Island nations reachable only by air or ocean within a continent (e.g. Madagascar, Cape Verde)
- Landlocked countries with limited road infrastructure
- Routes that cross hostile borders
- Any nuance below the continent level

The original limitation still stands: this is a coarse heuristic, not a real logistics feasibility engine. In the current Streamlit UI, clearly impossible intercontinental truck scenarios are now blocked before prediction, but everything else is still approximate.

---

## 5. RAG Context Is Static and Small 

The FAISS index contains **107 chunks** from a manually assembled corpus of freight logistics documents. It is not connected to the internet and does not update.

- Retrieval is based on cosine similarity to an embedded query, with a threshold of 0.45.
- If no chunk scores above 0.45, no context is returned and the LLM explanation will have less grounding.
- The corpus covers general freight modes and Sub-Saharan Africa corridors reasonably well, but is weak on specific lane-level pricing, Middle Eastern routes, and anything post-2025.
- "Market context retrieval year: 2026" in the UI means the query was tagged with 2026 - it does not mean the documents contain verified 2026 rates.

---

## 6. LLM Explanation Can Hallucinate

The AI Explanation is generated by a Groq-hosted LLM (llama-3.1-8b-instant by default) given the SHAP values, shipment details, and retrieved chunks. The LLM is instructed not to invent figures, but:

- Small open-weight models do occasionally confuse or round numbers.
- The SHAP dollar impact figures in the prompt are approximations (`|pred| x (exp(|shap|) - 1)`), not exact attributions.
- If the RAG context is weak or off-topic, the LLM may fall back on generic freight knowledge that is not grounded in the specific shipment.
- **Always cross-check the explanation against the SHAP table**, which is the ground truth.

---

## 7. What-If Chat Cannot Optimise Routes

The What-If Chat is a scenario tool, not an optimiser. It reruns the model with modified parameters and explains the delta. It will **not**:

- Find the cheapest route for you automatically
- Suggest which destination hub to use
- Know about carrier availability or lead times
- Account for customs, duties, or last-mile costs
- Search for real quotes

When you ask "give me a cheaper route," the LLM will classify this as informational or feasibility and retrieve RAG context. It will not enumerate alternatives.

---

## 8. Mode Encoding Is Coarse

The model sees mode as a single encoded integer (Air=0, Ocean=1, Truck=2, Other=3). "Air Charter" was collapsed into Air during training. This means:

- The model cannot distinguish charter vs scheduled air.
- "Other" is a catch-all that includes modes seen rarely in training; its predictions are the least reliable.
- The SHAP value for `mode_encoded` reflects the historical average cost difference between modes, not the actual market spread for the specific corridor.

---

## 9. Weight Bucketing Loses Granularity

Weight is both used as `log_weight` (continuous) and `weight_bucket` (binned). The bin edges were set from the training data's distribution. Very large or very small shipments (outside the 99th percentile cap applied during cleaning) are clipped to the cap value. The model was not trained on extreme weights and will extrapolate poorly.

- This can create **flat prediction regions** where materially different inputs return the same number because the tree model lands in the same learned leaf.
- Example failure mode observed during validation: tiny parcel-style weights such as `1 kg` and `5 kg` can return the same baseline on weakly supported or unseen lanes.
- Another observed failure mode: extremely large requests such as `50,000 kg` and `500,000 kg` can saturate into the same high-weight region and return the same number.

---

## 10. No Contract Rates, No Actual Procurement Prices

USAID SCMS freight costs are **contracted programme rates** negotiated under PEPFAR and global health procurement frameworks. They are systematically lower than spot market freight rates. Predictions from this model should not be used to benchmark commercial freight procurement without a significant adjustment for the rate differential.

---

## 11. LLM Intent Parsing Can Misclassify

The What-If Chat uses an LLM to classify your message as `what_if`, `feasibility`, or `informational`. Misclassification can happen:

- A what-if question phrased ambiguously may route to RAG (informational) and return no prediction delta.
- A factual question about trade terms may be classified as what_if and trigger a useless rerun.
- If the LLM returns malformed JSON, the chat fails with an error.

If the chat gives a confusing response, try rephrasing more explicitly: "What if I change the mode to Air?" performs better than "what's cheaper?"

---

## 12. The Scenario Year Dropdown Is Partially Cosmetic

The current local app only exposes the scenario years with explicit support: `[2015, 2026]`.

Even so:

- The model year feature is capped at 2015 internally.
- RAG market context currently only exists for `2026` in the committed corpus.
- Selecting `2026` does **not** create a true 2026 forecast. It creates a 2015-equivalent model baseline plus 2026-tagged retrieved context.
- If more years are reintroduced into the UI in the future without new market corpus coverage, they must be treated as fallback years rather than real forecast years.

---

## 13. Brunel Dataset Was Dropped

The Brunel Shipping dataset was evaluated during Week 2 and excluded because it was identified as synthetic (generated) data. Only USAID SCMS data was used for training. This limits the diversity of lanes, commodities, and vendors represented.

---

## 14. Unsupported Scenarios Are Now Blocked in the UI, But Not Solved

The app now performs support checks before allowing a numeric prediction. This makes the demo more honest, but it does **not** mean the underlying modelling problem is solved.

Current blocker examples:

- Unseen origin->destination routes
- Unseen route/mode combinations
- Tiny parcel-style weights below the 1st percentile of training support for a mode
- Extreme weights above the 99th percentile of training support for a mode
- Clearly impossible intercontinental truck scenarios

These blocks exist because the model was producing numbers for cases it could not defend. Blocking them is better than showing misleading precision, but it also means the usable prediction domain is narrower than the raw form might suggest.

---

## 15. The UI Guardrails Are Heuristic, Not Formal Uncertainty Estimation

The validation logic in the Streamlit app is rule-based. It uses percentile thresholds, route coverage checks, and simple feasibility checks. It does **not** provide:

- calibrated prediction intervals
- conformal uncertainty bounds
- out-of-distribution detection from the model itself
- formal confidence scores

So when the UI shows a warning or blocks a case, that is an engineering safety rule, not a statistically rigorous uncertainty estimate.

---

## 16. Static RAG Context Is Not the Same as Live Market Data

The current app uses a local FAISS index over a static committed corpus. It does **not** fetch fresh internet data at runtime.

- This means the RAG layer can explain current market structure only to the extent that the local `market_2026/` files capture it.
- It cannot verify today's freight quote, today's fuel surcharge, or today's disruption status.
- Adding live web retrieval in a future version would improve freshness of context, but it would still **not** turn the model output into a real-time quote unless the numeric pricing logic itself was redesigned.

In other words: live retrieval could improve explanation freshness, but it would not magically fix unsupported numeric predictions.

---

## 17. The System Is Better for Structured Baselines Than for Real Quoting

This project is most defensible as a **structured baseline estimator plus explanation layer** for scenarios that resemble the USAID training distribution.

It is much less defensible as:

- a parcel quote tool
- a global freight marketplace estimator
- a 2026 or 2030 pricing engine
- a route optimisation system

If the user wants commercial-grade quoting, the right solution is likely a different product class entirely: carrier APIs, forwarder quote feeds, or a retrained model on recent commercial pricing data.

---

## 18. Read the Number as a Decision Aid, Not Ground Truth

The safest interpretation of the app's numeric output is:

- baseline directional estimate
- within a limited training distribution
- enriched by a destination-tier structural benchmark
- explained by static retrieval and an LLM

The number should help frame a conversation, not close one.

For any procurement, budgeting, or operational decision, the result should be checked against:

- current market quotes
- forwarder or carrier input
- corridor feasibility
- mode-specific operational constraints
